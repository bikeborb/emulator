### fix(maxwell3d): draw the small index buffer methods with their own index size and instance

DRAW_INDEX_BUFFER{32,16,8}_BEGIN_END_INSTANCE_{FIRST,SUBSEQUENT}
(clb197.h, 0x17e4 to 0x17f8) each draw one whole instance. Their
argument carries first, count and topology only, so the index size is
the one in the method's name; DrawIndexSmall used whatever index format
was set before. FIRST and SUBSEQUENT work like BEGIN's INSTANCE_ID:
FIRST flushes any deferred draw and draws instance 0, each SUBSEQUENT
the next one, with base instance = global base + count. NVK draws
instanced on Maxwell by repeating BEGIN with INSTANCE_ID SUBSEQUENT
(nvk_cmd_draw.c).

### fix(dma): translate SET_REMAP_COMPONENTS for pitch copies

With REMAP_ENABLE, LINE_LENGTH_IN counts elements of
SET_REMAP_COMPONENTS, not bytes, and each destination component is a
source component, CONST_A, CONST_B or NO_WRITE (clb0b5.h). Pitch copies
only handled the CONST_A fill. The destination components were also
read with a 3-bit stride; they are 3 bits wide but 4 bits apart.

RemapConst gains DstComponent, the element sizes, IsPlainCopy and
RemapElements; pitch copies with a remap that is not a plain copy go
through CopyRemapped, which reads the source first (so an overlapping
destination sees the old bytes) and keeps destination bytes for
NO_WRITE. The 4-byte CONST_A fill keeps its GPU clear.

src/tests/video_core/dma_remap.cpp holds the bytes a Switch wrote for
the same SET_REMAP_COMPONENTS values (dma_remap cases 1 and 2).

### fix(dma): remapped copies with a block linear side

Multi-line copies with REMAP_ENABLE that are not plain copies and have
a block linear source or destination (CopyRemappedRect): widths and
origins count elements on both sides, source elements on the source
and destination elements on the destination, as nvk_cmd_copy.c
(nouveau_copy_rect) programs them and as a Switch copies (maxwell-raw 3,
dma_block cases 1 and 3). The source is read in source elements, the
destination read, remapped (NO_WRITE keeps bytes) and written back in
destination elements.

### fix(fermi2d): blend operations and clipping in 2D blits

Every 2D blit whose operation was not SRCCOPY was dropped, and
SET_CLIP_* was ignored. SRCCOPY_AND, BLEND, SRCCOPY_PREMULT and
BLEND_PREMULT are now done by the software blitter, which reads the
destination and combines; ROP and ROP_AND are done as SRCCOPY and
logged once. A blit whose destination rect leaves the clip keeps the
destination pixels outside it.

Formulas from deko3d's engine_2d.def, checked on a Switch through
deko3d (blit2d-dk4, block linear BGRA8): BETA1 bits 30:23 as a fraction
of 255 (0xFF blends fully; the "1.31 fixed point" reading would give
255/256), BETA4 with B in bits 7:0 and A in 31:24 as cl902d.h defines
it. 47 of 48 measured pixels match exactly, one alpha is off by 1. Only
BETA1 0x7F800000 was measured, and blending happens after the source is
converted to the destination format. The measured table is the unit
test in src/tests/video_core/blit_operation.cpp.

### fix(sw_blitter): converters follow the Vulkan memory layout

The software blitter's converters read memory as the Vulkan format the
texture cache uses for the same render target format. 18 packed
formats (A8R8G8B8, A8B8G8R8, A2B10G10R10, B10G11R11, R5G6B5,
A1R5G5B5 and the X variants) had their channels reversed: the
converter read A from byte 0 of A8R8G8B8, which the texture cache
stores as B8G8R8A8. Channels a format does not store now read as
(0, 0, 0, 1), as Vulkan reads them; X8 formats had no or garbage
alpha. Float to UNORM/SNORM clamps and rounds to nearest, as Vulkan
converts and as the 2D engine stores blends on a Switch; before, values
wrapped and truncated and out-of-range SRGB values indexed past the
table. Tests in src/tests/video_core/blit_operation.cpp.

### fix(puller): translate MEM_OP_D's L2 sysmem invalidate

On gm20x MEM_OP_C/D replace MEM_OP_A/B (clb06f.h). MEM_OP_D OPERATION
L2_SYSMEM_INVALIDATE makes the GPU read what the CPU wrote, which is
what InvalidateGPUCache does; MEM_OP_A and C are operands only. Both
logged an error on every use before. MEM_OP_B keeps its old behaviour.

### fix(kepler_compute): release the QMD semaphores after a dispatch

A QMD can ask for up to two semaphore releases when its grid completes
(SEMAPHORE_RELEASE_ENABLE0/1 at bits 202 and 203, RELEASE0/RELEASE1 at
bits 736 to 927 of QMDV01_07, clb1c0qmd.h). They were ignored, so a
guest waiting on one waited forever. They are queued after the dispatch
as payload queries, as the DMA engine queues its release, four-word
releases with a timestamp. Releases with a reduction op are not
translated and logged once. static_asserts pin the QMD words.

### fix(maxwell3d): stop the channel at a report semaphore acquire

SET_REPORT_SEMAPHORE_D OPERATION_ACQUIRE makes the following work wait
until the word at the address equals the payload (COMPARISON_EQ) or is
at least it (_GE). The 3D engine ran past it, so the GPU could read a
command buffer the guest had not finished writing; Super Mario Galaxy
froze on a purple frame after logging thousands of "Special puller
engine method 1 not implemented" in 40 ms.

The acquire now stops the channel through the puller's existing acquire
(StartAcquire, shared with the GPFIFO acquire, with its give-up after
one second), via DmaPusher::AcquireSemaphore and a callback set in
ChannelState::Init. COMPARISON 0 is EQ (clb197.h); the enum named it
NotEqual.
