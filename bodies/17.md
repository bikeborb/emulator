### feat(core): allocate guest memory from the GPU driver on Android

Vulkan::ExportGuestMemory (vulkan_common/vulkan_guest_memory.cpp, new)
creates a throwaway instance and device on the first physical device and
allocates the guest's memory from the driver as exportable dma_buf
memory: total_size / chunk_size chunks (GuestMemoryChunkSize is 1 GiB),
each a buffer plus one allocation from the first memory type the buffer
allows that is device local, host visible, host coherent and host
cached, exported with vkGetMemoryFdKHR. Only on an integrated GPU with
VK_KHR_external_memory_fd and VK_EXT_external_memory_dma_buf; every
failure closes the descriptors and leaves guest memory as it was.

Common::HostMemory takes the descriptors (at most MaxBackingChunks) and
maps every chunk over a PROT_NONE reservation; a mapping that crosses a
chunk boundary is made in pieces (FirstChunkRange, with compile-time
checks and Linux test cases in tests/common/host_memory.cpp). With no
descriptors the memfd path runs unchanged. System::Impl calls the export
from InitializeKernel at every game start until it works, because the
Android frontend loads the driver after System::Initialize has created
guest memory.

This only provides guest memory the GPU can address; importing it into
the renderer's device is the next step. Logged once per attempt as
"Guest memory from the GPU driver: on (N chunks of M MiB)" or
"off (reason)". On the AYN Thor: on, 4 chunks of 1024 MiB, frame rates
unchanged in five games.
