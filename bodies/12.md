### fix(puller): write SEMAPHORED releases at their own fence

A SEMAPHORED RELEASE was queued as a sync operation and only reached guest
memory at the next fence. Hardware writes it when the release executes, so a
guest polling the semaphore without a fence of its own never saw it.

Use the same fence path as SemaphoreRelease (IsAFence).

Verified with maxwell-raw 2 (release_no_fence): written on a Switch,
missing for 500 ms in yuzu until a later fence.

### fix(puller): honour SEMAPHORED RELEASE_SIZE

Every SEMAPHORED release was written in the 16-byte form (64-bit value and a
timestamp at +8). RELEASE_SIZE (bit 24) can ask for 4 bytes; the 12 bytes
after the semaphore were then overwritten. Read the full OPERATION field
(4:0) as well, as clb06f.h defines it.

Verified with maxwell-raw (release_size): bytes 4-15 untouched on a Switch,
overwritten in yuzu.

### fix(puller): stop the channel at a failed SEMAPHORED acquire

SEMAPHORED acquires (ACQUIRE, ACQ_GEQ, ACQ_AND) never waited: the retry
was a `continue` inside `do { } while (false)`, so the channel ran on
whatever the semaphore held. maxwell-raw shows the Switch holding the
channel until the CPU writes the semaphore, and yuzu running past it.

Waiting in place would stop the only GPU thread, and with it any channel
that has to make the release. Volta's dev_pbdma.ref.txt (NV_UDMA_SEM_EXECUTE)
says Host stops the channel, switches to another one and polls the
semaphore when it comes back. This does the same:

- Puller: a failed acquire is recorded (address, payload, op) instead of
  passing. RetryPendingAcquire reads the semaphore again.
- DmaPusher: stops after the acquire word, keeps the remaining words and
  their address, and continues from them once the acquire passes.
  Puller methods in non-incrementing mode run one word at a time so the
  stop lands right after the acquire. DispatchCalls no longer resets
  dma_pushbuffer_subindex; before this change Step only stopped with an
  empty queue, where the index is already 0.
- Scheduler: keeps a list of stopped channels and retries them.
- GPU thread: while a channel is stopped, polls the queue and retries
  every 0.5 ms when idle (with a fence flush once per new work) and after
  each command (without one).
- ACQ_AND passes when (semaphore & payload) != 0, per dev_pbdma.ref.txt.
  The old test was `word && payload == 0`. ACQ_GEQ keeps its unsigned test.

Not hardware behaviour: after 1 s the emulator gives up, logs a warning
with the address, payload and value, and continues, so a release the
emulator never writes stalls the channel instead of hanging the game.

Not changed: SemaphoreAcquire (method 0x1A) still loops in place.
