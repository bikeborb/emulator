### build(dynarmic): bring Dynarmic e40fa8b into the tree

externals/dynarmic was a submodule; it is now an in-tree copy of the
commit it pointed at (e40fa8ba6d739807b0965c5e3a60e69f2353f209), so it
can change with the rest of the code. The submodule entry in .gitmodules
and the gitlink are gone. Dynarmic's own submodule gitlinks are dropped
with it: the build already takes fmt, xbyak, oaknut, zydis and the rest
from Citron's externals.

### fix(dynarmic): x64 backend compiles against this tree

backend/x64/block_of_code.h included "common/x64/xbyak.h", a path this
tree renamed to dynarmic_xbyak_abi.h, so the in-tree Dynarmic could not
build its x64 backend at all. The fastmem fallback maps in
a32_emit_x64.h and a64_emit_x64.h are keyed by std::tuple, for which
std::hash has no specialisation; common/container/tuple_hash.h (new)
provides one and the four declarations use it. Verified with the x86-64
Dynarmic test suite: 127 of 128 cases pass, the one failure predates
this change.
