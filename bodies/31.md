### fix(buffer_cache): skip and count unbacked pages on download write-back

A buffer can cover device pages no guest memory backs: a storage buffer
bound without a size spans its whole GPU mapping. Writing such a
download back logged once per unmapped page per flush (DOOM Eternal:
47,000 lines per boot). WriteBlockUnsafe returns the holes like
ReadBlockUnsafe and can leave them unlogged; the buffer cache's three
write-back paths go through WriteBackDownload, which skips them and
logs the first eight and every 256th.

### perf(buffer_cache): stream uniform buffers that would need an ordered copy in a render pass

A uniform buffer the guest rewrote while draws earlier in the frame
still use the cached copy needs an upload that keeps its place in the
command stream, because CanReorderUpload refuses to move it ahead. A
copy cannot run inside a render pass, so the pass ended before the draw
and began again after it, which on a tiled GPU stores and reloads every
attachment. Super Mario Galaxy's gameplay did this on every draw:
render passes equalled draws, about 12,500 a second.

Such a uniform buffer now takes the existing stream path (CPU memcpy, no
GPU copy) while a render pass is open; the cached copy stays marked
modified for its other users. Outside a render pass the normal sync
runs. Same scene on an AYN Thor (Turnip): 24-26 fps to 39-40, about 11
draws per render pass.

### fix(vulkan): track buffer usage per submission

Buffer usage tracking was cleared once a frame, between submissions,
which forgot draws already recorded in the open command buffer, so an
upload could be moved ahead of them. Usage now belongs to a submission:
MarkUsage resets the tracker when the scheduler tick changes, and
IsRegionUsed only counts use by the current submission, since work of
earlier submissions is ahead in queue order anyway.
