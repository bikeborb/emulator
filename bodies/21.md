### refactor: C++23, plain assert, std::unreachable

The build moves to C++23 (CMAKE_CXX_STANDARD 23, /std:c++latest,
-std=gnu++2b on Android) and the assertion macros go:

- ASSERT and DEBUG_ASSERT are assert; ASSERT_MSG(expr, "msg {}", arg) is
  assert(expr && "msg {}" && (void(arg), true)), so the message stays
  next to the condition and nothing is evaluated for it in release
  builds; UNREACHABLE and UNREACHABLE_MSG are std::unreachable() with
  the message kept as a comment. 1,713 sites in src/, 1,692 in Dynarmic.
- 87 sites in src/ and 3 in Dynarmic did work inside the condition
  (inserts into the address space, iterator increments, counters); that
  work is hoisted out so it still happens when assert compiles out.
- common/assert.h keeps UNIMPLEMENTED, UNIMPLEMENTED_MSG,
  UNIMPLEMENTED_IF and ASSERT_OR_EXECUTE, which log or fall back rather
  than abort; common/assert.cpp and the use_debug_asserts setting (and
  its debug dialog entry) are gone. R_ASSERT evaluates its expression in
  every build and asserts the result.
- Dynarmic uses <cassert> and <utility> directly; its own assert.h, the
  Citron shims src/dynarmic/common/{assert,logging,common_types}.h, the
  mcl patches, the -UNDEBUG block, DYNARMIC_IGNORE_ASSERTS and the
  find_package fallback in externals/CMakeLists.txt are gone, and the
  CPM Dynarmic block is an add_subdirectory of the in-tree copy.
- C++23 fallout: libc++ in C++23 mode no longer pulls <algorithm> and
  <vector> in transitively (tz.h, settings_setting.h, fft.cpp), the
  std::string(0) constructor is deleted (fs_android.cpp), a constexpr
  unique_ptr destructor needs the complete type earlier (kernel.cpp),
  and locals that were only read by an assert are [[maybe_unused]].

Behaviour in release builds is unchanged except where an assert used to
do work, which now happens unconditionally. Checked on the AYN Thor: the
raw Maxwell semaphore tests give the same results and five games boot at
the same frame rates.
