### perf(buffer_cache): stop busy regions faulting page by page, skip needless padding

Three changes to the buffer cache, each measured on its own:

- A guest write into a watched page of a caching page the guest keeps rewriting now releases
  the rest of that caching page and the busy ones after it. Red Dead Redemption went from
  26,600 write faults a second on its render thread to 990, and from 30 to 42 fps with the
  speed limit off.
- Vertex streams that are not bound are skipped when binding (bit mask kept by
  UpdateVertexBuffer).
- Constant buffers are no longer copied and zero padded on every bind when the device has
  robustBufferAccess2, which already returns zero past the bound range.

### perf(buffer_cache): fill the usage bitmap in one go

Vertex streams are bound with their whole range, megabytes per call, and Track set the bitmap
one word per loop turn: 5% of the GPU thread in Red Dead Redemption. It is a memset now, and
tracking the range that was tracked last is skipped, since usage only grows until the reset.

Review fixes folded in:

Buffer cache: a widened write never marks less than was written. A
write that started near the end of a hot caching page and ran into a
cold one was cut to the end of the page, leaving the rest stale.

Constant buffers: robustBufferAccess2 checks the descriptor range in
steps of robustUniformBufferAccessSizeAlignment, so bytes past an
unaligned bound size can read the buffer instead of zero. The property
is now read, and a buffer whose bound size is not a multiple of it is
still zero padded. The step depends on the driver: one Turnip build on
the AYN Thor reports 1, another reports 16.
