### perf(vulkan): WAIT_FOR_IDLE as a deferred memory barrier

WAIT_FOR_IDLE was an event pair whose second scope was TOP_OF_PIPE,
which carries no memory dependency, and the event was never reset, so
every wait after the first did nothing. It is now a pipeline barrier
with a memory barrier, writes to all later reads and writes.

Recording that barrier ends the render pass, which on a tiled GPU
stores and reloads every attachment. Inside a render pass in which
nothing but attachments was written since the last barrier, the
barrier is deferred: later draws of the pass see attachment writes in
order. It is recorded at the next operation outside the render pass,
or before the next draw whose pipeline writes memory (storage buffers
or images, global memory, transform feedback), which ends the pass
first. Copies and clears that record their own barriers before and
after use a synced context that leaves nothing for a later wait.

FragmentBarrier no longer ends the render pass when barrier feedback
loops are on: a draw that samples a bound attachment ends the pass in
CheckFeedbackLoop and a draw to other targets starts a new one, so both
still get EndRenderPass's attachment barrier.

### perf(dma): GPU paths for plain remapped copies, and keep first-download state

TextureCache::DmaImageId forces a full GPU sync on the first DMA
download of an image (info.dma_downloaded). A game that maps the same
render target at a new GPU address every frame got that sync on every
download: Super Mario Galaxy spent 220-250 ms a second in
DownloadMemory -> runtime.Finish(), about 130 drains a second. A new
image that takes over an overlap now inherits dma_downloaded.

The GPU paths of block linear to pitch and pitch to block linear copies
take widths and origins in bytes. With REMAP_ENABLE they count
elements; a remap that keeps every component in place is a byte copy of
element size times as many bytes, so ScaleForPlainCopy scales them and
the GPU path is used. Any other remap, or an origin that no longer fits
its 16-bit field, takes the CPU path.

Same Galaxy scene on an AYN Thor: drains 0 ms a second, 41-45 fps to
46.
