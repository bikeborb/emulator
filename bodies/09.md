### fix(dynarmic): keep compiled blocks cached on arm64 release builds

The pinned dynarmic defines ASSERT as assert(), and the arm64 backend stores
every compiled block from inside ASSERT(...) in AddressSpace::Emit. A release
build defines NDEBUG, which removes the three inserts together with the
assert. Nothing is ever cached: each block is compiled again every time it is
reached, and the list RelinkForDescriptor walks only grows.

Every 32-bit game goes through this path on Android, since NCE cannot run
them. Mario Kart 8 Deluxe (base game, 32-bit) sat at 0 fps with one thread at
100 percent, 91 percent of it in RelinkForDescriptor.

Compile that one file with -UNDEBUG so its asserts stay alive. The submodule
is not touched.

AYN Thor, Mario Kart 8 Deluxe at the loading screen: 0 fps before, 59.6 fps
after.
