### fix(vulkan): pass the colour clear value through as raw words

SET_COLOR_CLEAR_VALUE holds the clear colour as raw 32-bit words in
the render target's numeric type: floats for float and normalized
targets, integers for integer ones (clb197.h). NVK and nouveau pass the
words through. The rasterizer instead read them as floats and, for
integer targets, scaled them by the component size, so an integer
target was cleared to a value derived from a float bit pattern.

VkClearColorValue overlays the same three types, so the four words are
copied as they are.

### fix(vulkan): clear the area SET_CLEAR_SURFACE_CONTROL asks for

CLEAR_SURFACE writes the render area cut down by scissor 0, the clear
rect and viewport clip 0 when SET_CLEAR_SURFACE_CONTROL USE_SCISSOR0,
USE_CLEAR_RECT and USE_VIEWPORT_CLIP0 ask for them (clb197.h; NVK
emit_clear_rects). Only the scissor was applied, and the clamp to the
render area ignored the scissor's offset. The clear rect max is
exclusive, and window rectangles flip like the scissor for a lower left
origin.

RESPECT_STENCIL_MASK (bit 0) decides whether the stencil write mask
applies to the clear; without it every stencil bit is cleared.

### fix(vulkan): masked colour clears per attachment slot and numeric type

Masked colour clears used a blend with constant colour factors to keep
the masked components. Integer formats cannot blend, and the pipeline
had one blend entry, so a masked clear of render target n > 0 wrote
render target 0, and masked stencil clears wrote undefined colour to
render target 0.

The clear pipelines now have one blend entry per colour attachment slot
of the subpass (Framebuffer::NumColorAttachments, the highest bound
target plus one, as vk_render_pass_cache.cpp builds the subpass). Only
the cleared slot is written, through the colour write mask, no
blending. The clear shader comes in float, uint and sint variants to
match the attachment's type, and takes the raw clear words.
