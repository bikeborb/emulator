### feat(android): stats panel on the second screen of the AYN Thor

The AYN Thor has a second built-in screen below the main one. While a game
runs, it now shows frame rate, speed, GPU driver, shader builds and three
settings there. The touch overlay finds its Activity through context
wrappers, so it keeps working when the activity is wrapped.

Two things in native.cpp go with it. getGpuDriver answers with an empty
string until the renderer exists, because the second screen asks as soon
as the activity resumes. PerfStats gives every reader the same one second
window, because reading the stats also reset them and three overlays read
them.

The resolution label uses the values in rendererResolutionValues.

### fix(android): game on the main screen, panel only on dual-screen handhelds

The second screen code ran on every device that reported more than one
display. It took the first display that was not the default one, put the
stats panel on it and hid the touch controls. A phone that was casting or
plugged into a television lost its on-screen controls and showed the panel
on the television. On the AYN Thor, a game started from the bottom screen
stayed on the bottom screen.

- SecondScreen (new) finds the second built-in screen, and only on a
  handheld known to have one. Both of the Thor's panels report an internal
  type and an unknown connection, so the public API cannot tell its bottom
  screen from an external display. The handheld is named instead.
- EmulationActivity: when it opens on the second screen it starts itself
  again on the main screen and closes. It tries once, so it cannot loop.
- The panel is not shown when there is no such screen or when the game
  itself is on it. The toast that said the controllers had moved is gone.
