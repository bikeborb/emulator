### fix(vulkan): reinterpret copies into an image in TRANSFER_DST_OPTIMAL

ReinterpretImage transitions the destination to TRANSFER_DST_OPTIMAL
and then copied into it naming GENERAL
(VUID-vkCmdCopyBufferToImage-dstImageLayout-00180).

### fix(vulkan): include colour attachment access in blit and resolve barriers

The blit and resolve barriers left colour attachment writes out of the
source scope and colour attachment access out of the destination scope,
so a blit of an image just rendered to, or rendered to right after, was
not ordered against that rendering.

### fix(vulkan): include transfer access in image upload barriers

An upload can follow another upload or a copy into the same image, and
a copy or blit can read the image right after it. The upload barriers
now include transfer writes before and transfer reads after.

### fix(vulkan): keep the DrawTexture blit source in GENERAL

The DrawTexture blit moved its source to READ_ONLY_OPTIMAL while the
descriptor it binds says GENERAL, and every other path assumes GENERAL.
The barrier now keeps GENERAL, covers every level and layer, and makes
shader, colour attachment and transfer writes visible to the fragment
shader.

### fix(vulkan): make the uint8 index pass output visible to index reads

The converted indices are bound as the index buffer, so the barrier
after the pass targets INDEX_READ, not VERTEX_ATTRIBUTE_READ.

### fix(vulkan): make device writes visible to the host for downloads

A fence does not make device writes visible to the host (Vulkan spec,
synchronization chapter). Download copies of buffers and images now end
with a barrier whose destination includes the HOST stage. Host-visible
buffers (upload, download, stream) are allocated HOST_COHERENT, which
every implementation offers, so the staging pool needs no flush or
invalidate on its mappings.

### fix(vulkan): full access masks around the ASTC decode pass

The ASTC decode pass waited only for shader writes before writing the
image and made its writes visible only to shader access after. The
image can be copied, blitted, rendered to or sampled on either side,
so both barriers use memory access.

### fix(vulkan): order the MSAA copy pass after earlier work

The MSAA copy pass read and wrote its images with no barrier before the
dispatch, although the source was usually just rendered to and the
destination may still be read. A barrier now orders both, and the
barrier after covers every later access.

### fix(vulkan): wait for the previous frame before a present layer upload

The present layer upload waited only for host writes, but the previous
frame may still be reading the image; the first scope now includes
ALL_COMMANDS.

### fix(vulkan): order reordered buffer uploads after earlier submissions

An upload moved to the upload command buffer runs before this
submission's work, but work of earlier submissions may still read or
write the buffer. The copy now waits for everything earlier on the
queue.

### fix(vulkan): whole-image barrier ranges for 3D images

A 2D or 2D array view of a 3D image (rendering to slices) got a barrier
range of its own slice. Without maintenance9 a barrier on a 3D image
covers every slice anyway and must use base layer 0, so any range on a
3D image now starts at layer 0 with VK_REMAINING_ARRAY_LAYERS.

### fix(vulkan): hold the submit mutex around vkDeviceWaitIdle

vkDeviceWaitIdle needs every queue externally synchronized. BlitScreen
::WaitIdle and ~RendererVulkan called it without scheduler.submit_mutex,
which the worker's submits and the present thread's submit and present
hold (validation: VkQueue threading error).
