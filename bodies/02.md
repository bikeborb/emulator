### perf(vulkan): keep the Z-pass counter on the CPU on Adreno, Mali and Turnip

On these drivers the host occlusion query result is already unused on
the GPU side: PresyncWrites drops the pending sync and
HostConditionalRenderingCompareValues always draws. What was left was
one host query per report plus a blocking vkGetQueryPoolResults for
each batch, and on a tile based GPU that wait costs most of the frame
in a game that reports a lot.

Red Dead Redemption takes two reports around every object and puts the
colour pass under RenderEnable IfNotEqual on the pair, about 770
reports and 350 conditional blocks per frame at Armadillo Station. On
a Snapdragon 8 Gen 2 with Turnip that scene ran at 4 fps, with the
guest cores idle and waiting. With this change it runs at 22.

Keep the counter on the CPU for these drivers instead. Each stretch of
draws made with the counter enabled adds a fixed number of samples, a
reset zeroes it, and two reports with no draw between them stay equal.
The value is final when the report is taken, so it is written to guest
memory at once and the query is freed. Render enable conditions on
those reports are then evaluated from guest memory by the existing
fallback in Maxwell3D.

Other drivers are not touched.
