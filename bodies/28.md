### fix(shader): name the IR opcode when an emitter is missing

The unimplemented emitters only say "SPIR-V Instruction is not
implemented". EmitInst appends the IR opcode, so the log names the
instruction a failed shader needs.

### fix(shader): 32-bit global memory atomics

32-bit global atomics (IAdd, SMin, UMin, SMax, UMax, And, Or, Xor,
Exchange) whose address was not tracked to a storage buffer threw at
emit time, and the whole shader failed to build. They now use the same
run-time search over the shader's storage buffers as untracked global
loads and writes, and return the old value, or 0 when no storage buffer
holds the address. Inc/Dec, 64-bit and float global atomics still
throw.

### fix(shader): search every storage buffer for untracked global memory

The run-time search for untracked global memory skipped every storage
buffer descriptor whose index was not set in nvn_buffer_used. That
bitset is indexed by NVN slot, not by descriptor, so a buffer tracked
from another constant buffer (DOOM Eternal keeps its table in cbuf 5)
was never searched and the fallback functions came out empty. Every
storage buffer whose constant buffer the shader declares is searched
now. The branch chain grows with the number of storage buffers.

### fix(shader): follow the 8/16-bit storage and uniform access features

8/16-bit loads and stores in storage buffers need storageBuffer8/16-
BitAccess, and 8/16-bit loads from uniform buffers need
uniformAndStorageBuffer8/16BitAccess. The backend used shaderInt8 and
shaderInt16 for both. Turnip reports the uniform ones false (Mesa
tu_device.cc). The profile carries the four features separately and
the device reports them.

### fix(shader): sized storage image formats decide the integer type

A storage image accessed with a sized format (SULD.D, SUST.D, SUATOM)
is bound through a view of that format (ImageView::StorageView), so the
format decides whether the image is integer. The texture's own format
was used, so raw R32UI reads of a float texture were declared f32 on an
R32_UINT view (VUID-vkCmdDispatch-format-07753). Typeless accesses and
image buffers keep the texture's format.

### fix(shader): texture tables indexed by a multiple, not only a shift

A 16-bit texture table entry is read at field * scale + base. The
tracker only followed a shift, so a table of records whose size is not
a power of two (an XMAD by a constant, DOOM Eternal multiplies the
material index by 10) was not followed, and the search walked on into
the index and bound it as the texture. TrackTableOffset follows IMul32
by a constant as well as shifts, and the descriptors carry a scale
instead of a shift.

### fix(vulkan): uint8 index pass without 8/16-bit storage, on every driver

vulkan_uint8.comp declared uint8_t and uint16_t storage buffers, so its
SPIR-V needed UniformAndStorageBuffer8BitAccess and
StorageBuffer16BitAccess; on a device without them, Turnip for one,
creating it broke VUID-RuntimeSpirv-storageBuffer8BitAccess-06328. It
also bound the index buffer's byte offset straight as a storage buffer
offset, which breaks VUID-VkWriteDescriptorSet-descriptorType-00328
whenever minStorageBufferOffsetAlignment is above 1 and the offset is
not a multiple of it. On Qualcomm's driver the pass was not built at
all, and a uint8 index draw without VK_EXT_index_type_uint8 bound the
8-bit buffer as 16-bit indices.

The shader now reads and writes uint words: each thread writes two
16-bit indices, reading each byte from the word that holds it; 0xFF
still becomes 0xFFFF. The input descriptor starts at the last aligned
offset before the first index and a push constant gives the residual
byte. The pass is built on every driver.

Checked offline with lavapipe on a device with no 8/16-bit storage
feature: 1100 index count and offset cases, 0 failures, no validation
message.

### fix(vulkan): storage views with the identity swizzle

A typeless storage access (SULD/SUST/SUATOM without a format) bound the
sampled view, which carries the TIC swizzle, but a storage descriptor
needs the identity swizzle (VUID-VkWriteDescriptorSet-descriptorType-
00336). It now gets a view shaped like the sampled one, in its format,
with STORAGE usage and the identity swizzle. What a swizzled TIC does to
a Maxwell surface load has not been tested on hardware, so a dropped
swizzle that is not the identity is logged.

### fix(shader): Flat only on fragment integer inputs

An integer input of a fragment shader must be Flat (VUID-StandaloneSpirv-
Flat-04744) and no input of a vertex shader may be (Flat-06202). The
sample id and the subgroup masks were not decorated, while primitive id
and layer were decorated in every stage. All integer inputs are now
decorated Flat in fragment shaders only.

### fix(shader): declare StorageImageExtendedFormats or drop the format

Storage images in R8ui, R8i, R16ui, R16i, Rg32ui, Rg32i and Rg32f need
the StorageImageExtendedFormats capability (SPIR-V core grammar), which
the module did not declare. It is declared when the device has
shaderStorageImageExtendedFormats; otherwise such an image is declared
without a format, as a typeless one is.

### fix(shader): treat all four components of generic 31 as generic

IsGeneric tested attribute <= Generic31X, so the Y, Z and W components
of the last generic fell through to the non-generic paths ("Read
attribute Generic[31].Y is not implemented").
