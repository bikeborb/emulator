### fix(vulkan): a lowered passthrough geometry shader does the last-stage work

A guest passthrough geometry shader stays one only with
VK_NV_geometry_shader_passthrough. Without it (every non-NVIDIA driver)
it is lowered to a geometry shader that emits the vertices itself, and
that shader does the last-stage work: depth mode conversion, fixed point
size, transform feedback. MakeRuntimeInfo treated every passthrough
shader as absent, so the vertex stage did that work too, and depth
conversion ran twice on drivers without depth clip control.

### fix(vulkan): remap generic locations into the geometry shader's input limit

Maxwell has 32 generics, but a geometry shader gets
maxGeometryInputComponents / 4 input locations (16 on Turnip), and a
pipeline whose geometry shader reads generic 16 or above broke
VUID-RuntimeSpirv-Location-06272. When a geometry shader is present and
the host has fewer locations, one table per pipeline gives the generics
the geometry shader reads from the stage before it the lowest
locations, in order, and the rest follow. The stage before uses it for
its outputs and the geometry shader for its inputs; other interfaces
keep the generic index.

### tools(shader_tool): geometry passthrough mask, location tables and an IR dump

- --gp-mask sets post_vtg_shader_attrib_skip_mask: the default 0
  passes every attribute through a passthrough geometry shader,
  built-ins included, which the emulator never sees.
- --in-locations / --out-locations set the generic location tables.
- --ir prints the optimised IR and the load, store and passthrough
  masks.
- Stages after the vertex shader get "previous stage stores
  everything", not only the fragment stage.
- The default profile targets SPIR-V 1.6, what a Vulkan 1.3 device
  gets: it enables SPV_KHR_workgroup_memory_explicit_layout, which
  needs 1.4.

### fix(vulkan): pass the layer through a lowered passthrough geometry shader

Vulkan has no Layer input in a geometry shader, so lowering a guest
passthrough geometry shader dropped a passed-through layer. When the
geometry shader passes the layer through and is lowered, the stages
before it are translated without layer output from vertex shaders, so
the existing emulation writes the layer to a spare generic, and
LowerGeometryPassthrough copies it from vertex 0 to Layer. ViewportIndex,
PointSize and ClipDistance passthrough are still dropped by the
lowering.
